# Long

— _Don't be long. Get stuff done. 🚀_

Long is a simple app to keep track of all the things you need to get done. Simply type out what you need to do and let on-device [Apple Intelligence] create your tasks for you.

<br/>
<br/>

# Features ✨

- ✍️ **Task Capture** — Type out things you need to do and on-device Apple Intelligence will extract the tasks
- 🗂️ **Task Sheets** — Group related tasks together with a task sheet for home, work or a project
- 🎯 **Focus** — Focus on tasks that are overdue, due today, scheduled, anytime or completed
- 📅 **Reschedule** — Move tasks to today, tomorrow, next week or anytime in a single tap
- 🔍 **Search** — Search across all, active or completed tasks
- ↩️ **Undo & Redo** — Undo and redo changes made to a task sheet and its tasks
- 🔔 **Notifications** — Daily reminders for tasks that are overdue or due today, sent at a time of your choosing
- 🎨 **Customise** — Set your name, appearance and preferred date format
- 📱 **On-Device** — Tasks are captured on-device and stored locally

# Local Development 👨🏻‍💻

To get up and running with local development you must follow all steps in the below sections.

> ⚠️ _**WARNING** — You must be running macOS with [Xcode] `>= 27.0` installed_

## Install Xcode

1. Download and install [Xcode] `>= 27.0` from the Mac App Store
2. Open Xcode and install the iOS `27.0` platform when prompted
3. Verify you are running a version of Xcode `>= 27.0`

```sh
$ xcodebuild -version
Xcode 27.2
Build version 27B52
```

## Install XcodeGen

The Xcode project is generated from the [`project.yml`](/project.yml) using [XcodeGen] and is not committed to the repository.

1. Download and install [Homebrew]
2. Run `brew install xcodegen` to install [XcodeGen]

```sh
$ brew install xcodegen
```

3. Verify XcodeGen is installed

```sh
$ xcodegen --version
Version: 2.46.0
```

Check out their official [installation guide](https://github.com/yonaskolb/XcodeGen#installing) for more info.

## Generate Project

1. Run `xcodegen` in the project root to generate the `Long.xcodeproj`
2. Run `open Long.xcodeproj` to open the project in Xcode

```sh
$ xcodegen
$ open Long.xcodeproj
```

> ⚠️ _**WARNING** — The `Long.xcodeproj` and `Info.plist` are generated by [XcodeGen] and are throwaway, so they should **NEVER** be edited directly. Any changes to the project such as build settings, dependencies or fonts **MUST** be made in the [`project.yml`](/project.yml) and the project generated again, otherwise they will be lost_

> 📝 _**NOTE** — Swift packages are resolved automatically by Xcode once the project is opened_

## Code Signing

The [`project.yml`](/project.yml) is configured with a specific development team. To run the app on a physical device you must change the `DEVELOPMENT_TEAM` to your own team ID and generate the project again.

## Start App 🚀

For local development there are two ways to run the app depending on your specific needs.

- [Simulator](#simulator) — Should be used when developing the app
- [Physical Device](#physical-device) — Should be used to test the app on real hardware

### Simulator

1. Select an iOS `27.0` simulator from the run destination menu
2. Press `⌘ R` to build and run the app

> 📝 _**NOTE** — Task capture in the simulator uses the on-device model on your Mac, so Apple Intelligence must also be enabled in your macOS settings_

### Physical Device

1. Follow the [Code Signing](#code-signing) section first
2. Connect your device and select it from the run destination menu
3. Press `⌘ R` to build and run the app

## Linting 🧹

Code is linted using [SwiftLint], which runs automatically on every build as a build tool plugin. Any warnings or errors are shown inline in Xcode.

> 📝 _**NOTE** — When building for the first time, Xcode will ask you to trust and enable the `SwiftLintBuildToolPlugin`_

> 📝 _**NOTE** — Lint rules are configured in the [`.swiftlint.yml`](/.swiftlint.yml) and should be relaxed there rather than with inline `swiftlint:disable` comments_

## Dependency Management 📦

Dependencies are managed using Swift Package Manager and are declared under `packages` in the [`project.yml`](/project.yml).
